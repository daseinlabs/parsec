# /trim — det+dir compaction of a session

`/parsec:trim` (or just `/trim` when unambiguous) is the plugin's better
`/compact`: instead of asking the model to summarize the session, it stages a
**deterministic needed-set trim** of the transcript (the chunks this session
actually re-read, edited, or used later — computed by `engine::needed`, no
LLM involved) plus a model-written **STANDING DIRECTIVES** block (durable
rulings, constraints, scope decisions). After you run `/clear`, the
SessionStart hook injects the composed payload as `additionalContext` into
the next session — one-shot, then the staged file is deleted.

Flow, from the user's side:

1. Run `/parsec:trim` when context is getting full.
2. The agent stages the deterministic trim (`parsec trim --json` or the
   `trim_stage` MCP tool) and reports estimated keep stats.
3. The agent extracts standing directives from its own in-context history and
   finalizes them (`parsec trim --finalize` / `trim_finalize`).
4. You run `/clear`. The next session in this project starts with the trimmed
   context pre-injected.

If step 3 never happens, the det-only payload is still injected — that is
the designed fallback, not an error. All token numbers around `/trim` are
chars/4 **estimates** and never enter the count_tokens savings ledger.

## Configuring the trim

### Aggressiveness level (1–5)

The single user-facing knob. `1` = low trimming (keep more), `5` = very high
(keep the least). Default `3` is the **only measured, parity-locked
configuration**; the other levels shift what counts as "used later" and are
unmeasured presets — deterministic, but estimates all the way down. Levels
are monotonic: a higher level never keeps more than a lower one.

Three ways to set it, highest precedence first:

1. **Ask in the command** — `/parsec:trim` with words to the effect of
   "aggressive" / "keep more" / "level 5". The skill passes `--level N` (or
   `trim_stage {level: N}`) through for you.
2. **`--level N` on the CLI** when running the binary directly:
   `parsec trim --level 4 --json`.
3. **`PARSEC_TRIM_LEVEL=N`** in the environment — the standing default when
   no explicit level is given. Values outside 1–5 are rejected.

### Environment variables

| Var | Default | Effect |
|---|---|---|
| `PARSEC_TRIM_LEVEL` | `3` | Default aggressiveness when no `--level`/skill argument is given (1–5). |
| `PARSEC_TRIM_TTL_SECS` | `1800` | Staged payloads expire after this many seconds. The user is told to `/clear` immediately; a stale trim injected into unrelated work is worse than none. |
| `PARSEC_TRIM_MAX_EST_TOKENS` | unset | If set and the trim body's estimated tokens exceed it, staging **refuses** (it never truncates). |

### CLI flags (direct `parsec trim` use)

The skill drives these for you; they matter for scripting and testing:

| Flag | Effect |
|---|---|
| `--level N` | Aggressiveness 1–5 (see above). |
| `--json` | Machine-readable stats on stdout. |
| `--finalize` | Read the STANDING DIRECTIVES from stdin and mark the staged payload `ready`. |
| `--transcript PATH` | Session transcript JSONL (default: newest for cwd under `~/.claude/projects`). |
| `--session-id ID` | Recorded in the staged payload (informational). |
| `--out PATH` | Stage here instead of `~/.parsec/trim/<project-key>.json`. |
| `--patch-file PATH` | Union a unified diff into the needed label as a gold stand-in (default off — the label is purely the session's own future use). |

Exit code 2 means the session is too short to trim (fewer than 6 steps /
chunks) or no transcript was found.

## Mechanics worth knowing

- Staged payloads live at `~/.parsec/trim/<project-key>.json`, keyed by the
  project directory; `consume_pending` verifies the cwd still matches before
  injecting and deletes the file after one use.
- Injection happens on `/clear` or a fresh session start — **not** on
  `--resume`.
- The keep-set is a pure function of (messages, patch, level config): no wall
  clock, no RNG. Level 3 equals `NeedCfg::det()`, the configuration the
  Python parity suite locks byte-for-byte.
- The directives block is generated by the session's own agent (the skill),
  never by the binary — no LLM call ships in `parsec`.
